# Security hardening — execution

Source: security audit of Nov 25, 2026 (findings 1–11 plus minors). Branch: `security/hardening`.

Global constraints
- Backend suite: `for f in backend-server/scripts/test-*.js; do node $f || exit 1; done` (no DB). iOS suite as in the network plan.
- Existing clients (iOS builds in the field, web) keep working; every change is backward compatible for honest clients.
- Never print user data in tests or probes. JS style per CLAUDE.md. Commit messages: short imperative sentence, no co-author trailer.

## Task 1: Safe TV Time zip reading (#1)
Files: `backend-server/lib/safeZip.js` (new), `backend-server/routes/import.js`, `backend-server/scripts/test-safe-zip.js` (new).
- Never extract to disk. Read only the required CSV entries by base name; refuse symlinks, entries with `..` or absolute paths, more than 2,000 entries, any needed entry over 100 MB uncompressed, or a total over 300 MB; write the CSVs to the job folder ourselves.
Test: crafted zips (symlink entry, traversal name, declared-size bomb, too many entries, a valid export). Expected: `safe zip: all passed`.

## Task 2: Verified email for Google and Apple linking (#3)
Files: `backend-server/lib/googleAuth.js`, `backend-server/lib/appleAuth.js`, `backend-server/lib/socialLink.js` (new), `backend-server/scripts/test-social-link.js` (new).
- Google: refuse unless `email_verified === true`. Apple: require `email_verified` true/'true' when an email is present.
- Link a provider to an existing account by email only if that account's email is verified (Task 3); otherwise refuse with a clear message.
Expected: `social link: all passed`.

## Task 3: Email ownership on accounts (#4)
Files: `backend-server/models/user.js`, `backend-server/routes/users.js`, `backend-server/lib/userHelpers.js`, `backend-server/scripts/backfill-email-verified.js` (new), `backend-server/scripts/test-email-policy.js` (new).
- `emailVerified` flag: true for accounts created via Google/Apple with a verified email and after a successful reset-link password reset.
- `updateProfile`: store emails lowercase; "taken" check case-insensitive; changing the email clears `emailVerified`.
- Backfill script (preview by default): existing accounts whose email matches a linked Google/Apple identity get `emailVerified: true`.
Expected: `email policy: all passed`.

## Task 4: Profile reads are self-only (#5)
Files: `backend-server/routes/users.js`, `backend-server/scripts/test-users-self.js` (new).
- `GET /users/getUser/:id` answers only for the caller's own id (404 otherwise); response omits provider ids.
Expected: pass.

## Task 5: Token revocation on password change and reset (#7)
Files: `backend-server/models/user.js`, `backend-server/authenticate.js`, `backend-server/routes/users.js`, `backend-server/scripts/test-token-revocation.js` (new).
- `passwordChangedAt` set on change/reset; tokens issued before it are rejected. Tokens get `iat` (already standard).
Expected: pass.

## Task 6: Complete account deletion (#8)
Files: `backend-server/services/accountDeletion.js` (new), `backend-server/routes/users.js`, `backend-server/scripts/test-account-deletion.js` (new).
- Delete every per-user collection, discovered from the models (any schema with `userFrom`), plus devices and the user.
Expected: test enumerates every model with `userFrom` and asserts each is covered.

## Task 7: Forgot-password never reveals accounts (#9)
Files: `backend-server/routes/users.js`. Same 200 response and body for known and unknown emails; mail failures logged, not reported.
